# HTTP Platform Module

## 🚀 Quickstart (30-second Onboarding)

Import `HttpModule` once in the application composition module. It registers the request context, Zod validation pipe, Problem Details exception filter, and response envelope interceptor globally.

```ts
import { Module } from '@nestjs/common';
import { HttpModule } from '@platform/http';

@Module({ imports: [HttpModule] })
export class CoreModule {}
```

Return ordinary values from controllers; the interceptor wraps them with `data` and `meta.request_id`. Return a `PaginatedResult` to include pagination, or mark a controller/handler with `@RawResponse()` (imported from `@platform/http/api`) when it must own the full response, such as health endpoints.

```ts
import { Controller, Get } from '@nestjs/common';
import { createPaginatedResult } from '@platform/http/api/pagination';

@Controller('assets')
export class AssetsController {
  @Get()
  list() {
    return createPaginatedResult([{ id: 'asset_123' }], {
      type: 'page',
      page: 1,
      page_size: 20,
      has_next: false,
      has_prev: false,
    });
  }
}
```

## 🗺️ Architecture Overview

`HttpModule` composes shared request processing at the application boundary and exposes the `/api/v1` prefix and `X-Request-Id` header constants. Its API helpers define response and pagination contracts, while the global pipe, filter, and interceptor adapt Nest requests and handler results to those contracts.

HTTP route policy metadata is also a platform concern: `@PublicRoute()` marks an intentional anonymous entry point, and `HTTP_ROUTE_POLICY_METADATA` carries generic policy labels for application guards. The platform does not interpret IAM permission codes or depend on the IAM module. Business modules define their own authenticated and capability decorators on top of this metadata.

## ⚡ Cheat Sheet

| Common Task | Service/Port to Inject | Method/Usage |
| --- | --- | --- |
| Enable shared HTTP behavior | None | Import `HttpModule` once in the root composition module. |
| Return a single resource | None | Return the value; it is wrapped as `{ data, meta }`. |
| Return a list | None | Return an array; it is wrapped as `{ data, meta }`. |
| Return pagination | None | Use `createPaginatedResult(items, pagination)` from `@platform/http/api/pagination`. |
| Keep a raw response | None | Add `@RawResponse()` from `@platform/http/api`. |
| Parse pagination query parameters | None | Use `pagePaginationQuerySchema` or `cursorPaginationQuerySchema`; defaults are page 1 and size 20, with size capped at 100. |
| Map an exception in a focused unit | None | Call `mapExceptionToProblemDetails(exception, path, requestId, isDevelopment)`. |

## ⚙️ Configuration Reference

This module has no module-specific environment variables or registration options. `API_PREFIX` (`api/v1`) is applied by `main.ts`; readiness and liveness paths are excluded from that prefix there.

| Property | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| `API_PREFIX` | string literal | `api/v1` | No | Application bootstrap's global REST prefix. |
| `REQUEST_ID_HEADER` | string literal | `X-Request-Id` | No | Header carrying the generated request ID. |
| `DEFAULT_PAGE_SIZE` | number | `20` | No | Default applied by both pagination query schemas. |
| `MAX_PAGE_SIZE` | number | `100` | No | Largest accepted pagination page size. |

## ⚠️ Gotchas & Pitfalls

- `HttpModule` must be imported into the active Nest application for its global providers and request context to run.
- Query schemas are strict: unknown query keys fail validation. `page_size` is coerced to an integer between 1 and 100; page pagination also requires a page number of at least 1.
- Standard response wrapping applies only to HTTP handlers. A `204 No Content` response passes through, and `@RawResponse()` bypasses wrapping.
- Pagination wrapping requires an actual `PaginatedResult` instance. A structurally similar plain object is treated as ordinary response data.
- Request IDs are generated by the module for every request and returned in `X-Request-Id`; the response envelope includes that ID. An active OpenTelemetry span contributes `trace_id` when one is available.
- Unexpected exceptions are logged and mapped to Problem Details. Their message is shown only in development; other environments receive a generic detail. Readiness `503` responses retain Terminus's JSON response shape.
